# ADR-20261004 Compute Lease Domain (sdkwork-compute)

- Date: 2026-10-04
- Status: accepted (owner-directed greenfield design; formal review pending)
- Requirement: [REQ-2026-1004](../../product/requirements/REQ-2026-1004-compute-lease-domain.md)
- Related: REQ-2026-0730 / ADR-20260730 (hybrid execution placement),
  `agent-execution-placement-orchestration.contract.json`,
  ADR-20260731 (task scheduling)

## 1. Context

Three pre-launch modules model compute independently:

- `sdkwork-sandbox`: `sandbox_instance` (TEXT ids, resource shapes,
  assurance levels: host_user / container / user_space_kernel / micro_vm /
  dedicated_vm) plus runtime bindings and session leases;
- `sdkwork-agents`: `ai_agent_execution_host` (dispatch hosts, capacity,
  drain) and `ai_agent_session_execution_placement` (session affinity,
  lifecycle, lease evidence);
- `sdkwork-webserver`: `webserver_cluster_host` / `webserver_cluster_instance`
  (machine inventory with heartbeats, process instances with health).

Shared platform conventions are already identical (snowflake BIGINT ids,
uuid, tenant sentinel `0 = platform-shared`, optimistic versions, soft
deletes, partial indexes). The divergence is vocabulary and ownership: three
lifecycle state machines, three node inventories, no cross-module matching
of capability to capacity.

## 2. Decision

Create the **`sdkwork-compute` capability module** — the single owner of
compute nodes, rentable instances and allocations. Sandbox, agents and
webserver become compute consumers.

### 2.1 Domain model (PostgreSQL baseline, DATABASE_SPEC profile)

```text
compute_node        算力节点(Inventory)
  id, uuid, tenant_id (0 = platform pool), node_id, display_name
  node_kind          docker | micro_vm_pool | bare_metal | cloud_pool
  dispatch_endpoint  opaque, credential-free
  region, assurance_capabilities JSONB   -- host_user/container/
                                         -- user_space_kernel/micro_vm/
                                         -- dedicated_vm
  capacity_vcpu, capacity_memory_mb, capacity_disk_mb, max_units
  status             registering | active | draining | disabled
  last_heartbeat_at, health_state          -- liveness telemetry (webserver DNA)
  metadata JSONB, version, audit columns, deleted_at
  UNIQUE (tenant_id, node_id); partial indexes for eligible-scan

compute_offering    租赁规格(SKU)
  id, uuid, tenant_id, offering_id, display_name
  vcpu, memory_mb, disk_mb, assurance_level, unit_basis (per_hour|per_day)
  status active | retired; version, audit

compute_instance    租出的算力实例
  id, uuid, tenant_id, instance_id, owned_by (subject)
  purpose            sandbox | agent_runtime | webserver | custom
  offering_id, node_id (allocated), vcpu/memory_mb/disk_mb, assurance_level
  state              requested | provisioning | active | suspended |
                     terminating | terminated | failed
  expires_at, renewed_until, endpoints JSONB, metrics JSONB
  workspace_ref (sandbox link), version, audit, deleted_at
  UNIQUE (tenant_id, instance_id)

compute_allocation  按需分配(调度绑定;generalizes agents placement)
  id, uuid, tenant_id, allocation_id
  consumer_domain    agents | sandbox | webserver | custom
  consumer_ref       consumer-scoped reference (e.g. agents placement id)
  instance_id, node_id
  requested/effective_target, state (agents placement 8-state vocabulary)
  lease_owner, lease_expires_at, fencing_generation
  version, audit; UNIQUE (tenant_id, allocation_id);
  partial UNIQUE current-per-consumer_ref
```

### 2.2 Ownership and integration

- `sdkwork-compute` owns the four tables and the App API
  (`/app/v3/api/compute/*`) + backend admin API; SDK families generated by
  the standard chain (materializer → sdkgen → validators).
- Consumers integrate via the compute SDK and persist only references:
  - agents: `ai_agent_session_execution_placement` gains
    `compute_allocation_id`; `ai_agent_execution_host` is **retired**
    (pre-launch: fold out of the baseline).
  - sandbox: `sandbox_instance` gains `compute_instance_id`; product
    metadata stays in the sandbox module.
  - webserver: `webserver_cluster_host/instance` migrate to
    `compute_node`/`compute_instance` (phase 3); site bindings keep
    references.
- The kernel keeps executing inside instances; compute owns the
  environment, the kernel owns the runtime SPI (unchanged boundary).

### 2.3 Reconciliation

One compute worker loop reconciles expired instance leases and lost nodes
(heartbeat liveness + allocation fencing), transitioning allocation state
and notifying consumers through allocation state — replacing the per-module
sweeps (agents placement sweep, sandbox lease sweeps) which become consumers
of allocation state.

## 3. Consequences

- `agent-execution-placement-orchestration.contract.json` remains
  authoritative for the agents-side transition; its ownership entry for
  admission moves to `sdkwork-compute` at phase 2 (contract revision,
  human-reviewed).
- Agents retires `ai_agent_execution_host` and shrinks to business
  aggregates + allocation references (net cohesion gain).
- The open-family generated-SDK refresh and codex rama migration remain
  independent external items.

## 4. Phased Roadmap

- **Phase 1 — compute module**: scaffold `sdkwork-compute` (baseline DDL,
  service, App API, worker), DATABASE_SPEC materialization + drift gates.
- **Phase 2 — agents integration**: placement binds to compute allocations;
  host table retired; contract revision; battery green.
- **Phase 3 — sandbox + webserver integration**: instance binding and host
  migration; per-module contract revisions.
- **Phase 4 — commercial metering**: offering pricing hooks and metering
  event publication.

## 5. Human Review

Protected areas touched: PostgreSQL schemas in three modules, kernel
boundary (unchanged but adjacent), public API additions (compute surface),
and cross-module ownership transfer. Owner direction recorded 2026-10-04
(workspace shell instruction: greenfield holistic design for compute rental
and on-demand agent runtime allocation). Formal REVIEW doc to follow before
phase 2 implementation.
